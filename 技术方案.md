# AI 健身教练（第一人称可穿戴 Agent）技术方案（V1）

## 一、系统概述

本系统为“具身智能健身教练（Embodied Fitness Agent）”，通过第一人称可穿戴设备实现：

* 实时视觉感知（POV Camera）
* 用户运动状态建模
* 健身房环境理解
* 动态训练规划与调整
* 长期训练行为建模与反馈

---

## 二、总体技术架构

```text
┌──────────────────────────────┐
│     可穿戴第一人称设备        │
│   (Camera + IMU + HR)        │
└──────────────┬───────────────┘
               ↓
┌──────────────────────────────┐
│        感知层 Perception      │
│ YOLO / MediaPipe / OCR       │
└──────────────┬───────────────┘
               ↓
┌──────────────────────────────┐
│     实时状态中枢 State Hub    │
│ Redis + Stream Processing     │
└──────────────┬───────────────┘
               ↓
┌──────────────────────────────┐
│   Agent Orchestrator (OpenAI)│
│   OpenAI SDK Agent           │
└──────────────┬───────────────┘
               ↓
┌──────────────────────────────┐
│        Skill 层              │
│ Planning / Tracking / Coach   │
└──────────────┬───────────────┘
               ↓
┌──────────────────────────────┐
│  知识层 + 向量数据库         │
│ PostgreSQL + pgvector        │
└──────────────────────────────┘
```

---

## 三、核心技术栈

| 模块      | 技术选型                       |
| ------- | -------------------------- |
| Agent框架 | OpenAI Agent SDK           |
| 后端服务    | FastAPI (Python)           |
| 数据库     | PostgreSQL                 |
| 向量数据库   | pgvector                   |
| 实时状态    | Redis Streams              |
| 视频流     | WebRTC / RTSP              |
| 目标检测    | YOLOv11                    |
| 姿态估计    | MediaPipe / ViTPose        |
| 动作识别    | Action Transformer / Mamba |
| 路径规划    | A* / Dijkstra              |
| 容器化     | Docker + Kubernetes        |

---

## 四、数据流总览

```text
视频流 + 传感器数据
        ↓
Perception Layer（结构化输出）
        ↓
State Hub（统一状态融合）
        ↓
Agent SDK（任务决策）
        ↓
Skill执行（规划/纠错/推荐）
        ↓
数据库 + pgvector（长期记忆）
```

# 五、数据结构设计（核心）

---

## 5.1 用户基础信息（user_profile）

```sql
CREATE TABLE user_profile (
    user_id UUID PRIMARY KEY,
    height FLOAT,
    weight FLOAT,
    age INT,
    gender TEXT,
    fitness_level TEXT,
    goals TEXT,
    created_at TIMESTAMP
);
```

---

## 5.2 实时生理数据流（biometric_stream）

```sql
CREATE TABLE biometric_stream (
    id BIGSERIAL PRIMARY KEY,
    user_id UUID,
    timestamp TIMESTAMP,

    heart_rate INT,
    hrv FLOAT,
    fatigue_score FLOAT,
    steps INT,

    imu_data JSONB
);
```

### 数据格式示例

```json
{
  "heart_rate": 132,
  "hrv": 42.5,
  "fatigue_score": 7.8,
  "steps": 1200,
  "imu_data": {
    "acc_x": 0.12,
    "acc_y": -0.03,
    "acc_z": 9.81
  }
}
```

---

## 5.3 健身房环境状态（equipment_state）

```sql
CREATE TABLE equipment_state (
    equipment_id TEXT PRIMARY KEY,
    name TEXT,
    location JSONB,
    occupied BOOLEAN,
    queue_count INT,
    last_updated TIMESTAMP
);
```

### 示例

```json
{
  "equipment_id": "bench_press_01",
  "name": "Bench Press",
  "location": {"x": 12, "y": 8},

  "queue_count": 3
}
```

```sql
CREATE TABLE workout_plan (
```

## 5.5 训练执行记录（exercise_execution）

```sql
CREATE TABLE exercise_execution (
    execution_id UUID PRIMARY KEY,
```

## 5.6 训练会话（workout_session）

## 5.7 长期记忆（pgvector）

```sql
CREATE TABLE memory_embedding (
    id BIGSERIAL PRIMARY KEY,
    user_id UUID,
    content TEXT,
    embedding VECTOR(1536),
    metadata JSONB,
    created_at TIMESTAMP
);
```

### 示例

```json
{
  "content": "用户在腿部训练后恢复较慢",
  "metadata": {
    "type": "recovery_pattern"
  }
}
```

# 十三、系统关键设计原则

---

## 1. State-first，而非 Prompt-first

系统核心不是LLM，而是：

```text
实时状态系统（State Hub）
```

---

## 2. Skill化而非Prompt工程

所有能力必须模块化：

```text
function-based intelligence
```

---

## 3. 长期记忆驱动个性化

```text
pgvector = 用户行为建模核心
```
