# 相对/趋势饮食洞察 —— Dashboard 能可靠展示什么

> **结论**:我们**对外不报绝对卡路里**(估不准、会抖、需绝对真值),但可以**可靠地报"相对/趋势"**——比较让系统性偏差自动抵消、且不需要绝对真值。这决定了 Dashboard(尤其[App IA v2.2](../../health_agent_prd.md)(§15)的**「画像」Tab + `/profile/lifestyle` 生活节奏详情页**)的主体是**"比较卡 / 趋势卡"**,而不是一个 kcal 大字。
>
> 本文做两件事:(1) 立三条原理,决定哪些"比"能做、哪些不能;(2) 发散出 Dashboard 能展示的卡片清单 + 口语词的可计算定义 + 落地约束。类型:解释/设计文档。
>
> 上游依据:本层吃 Plan B 感知结果(`scene` / `container` / `dish.category` / `BOM.prep_method` / 食材)+ 营养层的 `P/F/C 供能占比` 与 `能量档位`。见 [营养层-Agentic-RAG-设计.md](营养层-Agentic-RAG-设计.md)。

## 1. 三条原理(决定一切能不能做)

1. **偏差抵消 —— 只比"会让系统偏差对消"的维度**。
   绝对克数/kcal 估不准且有系统偏差;但**结构占比(P/F/C%)、类别(场景/做法/食材类)、频次/计数、排序**这些维度,同一套偏差在"比较"里两边对消。
   > `fat%` 比 `fat 克数` 稳;"这顿比上顿油"比"这顿 800 kcal"靠谱得多。**Dashboard 的指标必须从这一类里选。**

2. **聚合越多越可信 —— 信心随样本量上升**。
   单餐 vs 单餐 = 两个噪声点相减,**最抖**;周期 vs 周期 / vs 个人基线 = 噪声被平均掉,**最稳**。
   > 推论:**周期卡/基线卡可以下强断言;单餐对单餐只能当"软提示"**(可不可点开、可不可忽略)。Dashboard 的措辞强度要按这个分级。

3. **口语词必须落成可计算代理**。
   "油 / 重 / 缺蛋白 / 清淡 / 规律 / 多样"都得给一个**基于现有字段**的定义(见 §4),否则既算不出也没法评测。

## 2. 比较的两个维度:参考系 × 指标

任何一张卡 = **跟谁比(参考系)** × **比什么(指标)** × 方向 + 行动暗示。

### 2.1 参考系(跟"谁"比)

| 参考系 | 例子 | 信心 | 喂哪 |
|---|---|---|---|
| 上一餐 | "这顿比上一餐油" | 弱(两点相减) | 单餐详情/今日 |
| 同槽位的你 | "今天早餐比你平时早餐碳水高" | 中 | 单餐详情 |
| 近期滚动基线("比平时") | "比平时缺蛋白"(对比过去 14/30 天中位) | 中-强 | 画像维度卡 |
| 上一周期 | "本周比上周油" | 强 | 生活节奏页 |
| 你设的目标 | "本周蛋白达标 5/7 天" | 强 | 画像/我 |
| 同场景的你 | "你在这家店点的普遍比平时重" | 中(需场景样本) | 画像/主动建议 |
| 人群/同龄 | "你的蔬菜多样性高于同龄 60%" | 弱-中(**opt-in**) | 画像 |
| 膳食指南 | "今天红肉超过指南建议" | 强(冷启动可用) | 今日/画像 |

### 2.2 指标(比"什么"——只选偏差可抵消的)

| 指标 | 可计算定义(基于现有字段) | 现在能算? |
|---|---|---|
| 能量档位 | 营养层 band(轻/中/重/超重),比"档位"不比绝对值 | ✅ |
| 营养结构 P/F/C | 营养层供能占比% | ✅ |
| **油** | `fat%` ↑ 或 `BOM.prep_method ∈ {油炸,煎}` 出现频次 | ✅(prep_method 待确认在 schema) |
| **蛋白** | `protein%` 或蛋白源(肉/蛋/奶/豆)出现与否 | ✅ |
| 蔬菜量&多样性 | vegetable 类 dish/BOM 出现频次 + 不同蔬菜种类数 | ✅ |
| 碳水/主食 | `carb%` 或 staple 类出现 | ✅ |
| 场景分布 | `scene` 里 在家/外卖/快餐/餐厅 的占比 | ⚠️ 需确认 scene 已落 schema |
| 加工度 | 含品牌/包装 identity 的餐占比(现做 vs 包装/外卖) | ✅(brand/package 字段) |
| 餐次规律 | 餐次时间、间隔、漏餐、宵夜(>21:00) 频率 | ✅(靠 timestamp) |
| 食材多样性 | 一周内不同食材/食物类的去重计数(营养质量公认代理) | ✅(靠 BOM) |
| 重复度/单调 | 最近 N 餐里重复菜的占比 | ✅ |
| 含糖饮料 | beverage 类中含糖项频次 | ⚠️ 需要饮料子标记 |
| 红/白肉·植物蛋白比 | 蛋白源按 红肉/禽白肉/水产/植物 归类后的占比 | ✅(需食材→类映射,与召回那套复用) |

## 3. Dashboard 卡片发散清单(按聚合层级/信心,弱→强)

### A. 单餐即时对比(弱信心,软提示) → 单餐详情页趋势词 / 今日
- "这顿比你上一餐油"(fat% delta)
- "这顿蛋白够、蔬菜少"(餐内结构相对你的常态)
- "今天第一餐比平时晚了 2 小时"
- "这顿和你昨天午餐几乎一样"(单调提示)

### B. 日汇总(中) → 「今日」Tab 收尾
- "今天三餐:碳水偏高、蛋白偏低"(当日结构 vs 基线)
- "今天吃了 2 顿外卖"(场景计数)
- "今天没吃到蔬菜"(缺口检测)
- "今天整体比平时重"(当日能量档位 vs 基线)

### C. 周期趋势(强) → 生活节奏详情页
- "本周比上周油"(周 fat% 趋势)
- "连续 3 天碳水偏高"(streak)
- "本月在外就餐比例上升"(场景趋势)
- "本周吃了 23 种食材,比上周多"(多样性趋势)

### D. 基线偏离"比平时"(中-强) → 画像维度卡
- "比平时缺蛋白"(用户原话)
- "今天的油超过你平时 90% 的日子"(自身历史分位)
- "你最近红肉比平时多"

### E. 模式/画像(长程,雷达的 payoff) → 画像 Tab
- "你周末总比工作日油"(星期模式)
- "你晚餐通常最重"(餐次槽位模式)
- "你 80% 的高油餐发生在外食"(场景条件下的模式 → 直接可行动)
- "你这个月最常吃的 5 样"
- "你很少在家吃早餐"(习惯缺口)

### F. 目标进展(强) → 画像 / 我
- "本周蛋白达标 5/7 天"
- "你想少点外卖:本周从 5 次降到 3 次"(行为目标进展)

### G. 相关性洞察(最 actionable,需数据量) → 画像维度卡 / 主动建议
- "你吃得油的那几天,通常加班晚归"(× timestamp/作息)
- "你点外卖的那几顿普遍蛋白偏低"(跨指标相关)
> G 类是"雷达"的最高价值形态,但**最吃数据量和数据质量**,放到后期。

## 4. 口语词 → 可计算定义(reference)

| 口语词 | 定义 |
|---|---|
| 油 | `fat%` 高于个人基线,或 `prep_method∈{油炸,煎}` 频次升高 |
| 重 / 轻 | 能量档位(band)相对你的常态偏高/偏低 |
| 清淡 | 低 fat% + 蒸/煮 prep_method 为主 + 蔬菜占比高 |
| 缺蛋白 | `protein%` 低于基线,或连续若干餐无蛋白源 |
| 规律 | 餐次时间标准差小、无漏餐、宵夜频次低 |
| 多样 | 滚动窗口内去重食材/食物类计数高 |
| 重口/加工 | 含包装/外卖 identity 餐占比高 |

> 这些定义都该作为**可调阈值**写进配置,接 GroundTruth 后再标定(什么算"高"、窗口多长)。

## 5. 落地约束(设计/写代码必须遵守)

- **只用 `confirmed` 餐,`pending` 不进**(红线,见 [推荐闭环](#) / Pending Event)。
- **置信加权**:低置信餐降权或排除,别让一条乱识别带偏整周趋势。
- **冷启动**:新用户无个人基线 → 降级到 **vs 指南 / 日内对比**,并明确标"基线建立中"(别假装"比平时")。
- **方向 + 档位词,不报假精确**:"↑明显偏油"而非"+12.3% fat"(与对外点值"故意钝化"一脉相承)。
- **语气=雷达不说教**:沉默胜过聒噪,一日最多 1–2 条主动;比较卡默认是"观察"不是"批评"。
- **人群对比一律 opt-in**:避免羞辱/隐私问题。
- **每张卡尽量带"下一步"**:"比平时缺蛋白 → 下一餐加个蛋/豆制品" → 喂[推荐闭环] → 算[北极星采纳率]。这是相对框架的天然红利:**有了"偏离基线",建议就有了锚**。

## 6. 现在能做 vs 需补

| 能做(现有 Plan B + 营养层字段) | 需补 |
|---|---|
| A/B/D 大部分(结构、油、蛋白、能量档位、单调、缺口) | **场景类卡**:确认 `scene` 已稳定落 schema(v3 CLAUDE.md 列为已知缺口,Plan B 已加,需对齐) |
| C 周期结构/多样性趋势 | **含糖饮料卡**:beverage 需糖分子标记 |
| E 餐次槽位/星期模式 | **红白肉比、场景条件模式**:需"食材→类"映射(与召回 §4 那套复用) |
| F 目标进展(若用户设目标) | **足够 confirmed 餐量**:周期/基线/相关性卡都要样本(接 Alpha 5人×7天采集) |
| — | **G 相关性**:需更多数据 + 可选外部信号(日历/作息) |
