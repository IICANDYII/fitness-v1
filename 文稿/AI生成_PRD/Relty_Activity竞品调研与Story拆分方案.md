# Relty Activity 板块：竞品调研、设计机制与 Story 拆分方案

本文件整合了市面上所有相关全天活动（Activity）与健身监控类竞品（硬软一体、纯软件、数据聚合类）的深度调研，确立了 Relty Activity 板块的 UI 设计机制，并拆分了 4 个可执行、可验收的 Story 任务。

---

## 一、 市面竞品调研：UI 数据、分层与展示特点

### 1. 硬软一体主流竞品（Wearable-Dependent）

#### 1.1 WHOOP
*   **UI 数据分层**：
    *   *第一层（状态）*：今日 **Recovery（恢复度，0-100%）**、**Strain（累积压力负荷，0-21）**、**Sleep（睡眠）**。采用红（危险）、黄（维持）、绿（优异）三色表征。
    *   *第二层（归因）*：HRV、静息心率（RHR）、皮肤温度、血氧饱和度对基线值的偏离度百分比。
    *   *第三层（时序流）*：24小时连续心率折线、单次有氧运动心率区间（Zone 1-5）时间分布。
*   **展示特点**：**去数值化与“负荷-恢复配对”**。首屏核心是三个大圆环。WHOOP 认为“没有脱离恢复谈负荷的道理”，UI 会明确建议“你今天恢复了 80%，目标负荷区间是 12.0 - 15.0”。

#### 1.2 Apple Fitness
*   **UI 数据分层**：
    *   *第一层（状态）*：**Move（主动卡路里）**、**Exercise（锻炼分钟）**、**Stand（站立打断，12小时）**。
    *   *第二层（归因）*：按小时的主动能量消耗柱状图、久坐时段明细。
    *   *第三层（时序流）*：单次运动的心率曲线、配速折线、GPS 轨迹。
*   **展示特点**：**同心圆环闭合（Concentric Rings）**。极致的行为学激励（Gamification），利用徽章、周趋势、好友竞技迫使用户每天“合环”。

#### 1.3 Oura Ring
*   **UI 数据分层**：
    *   *第一层（状态）*：**Readiness（就绪度）**、**Sleep**、**Activity** 三个 0-100 的主分数。
    *   *第二层（归因）*：Contributors 能量条，划分为 Optimal、Good、Pay Attention 三档（如：睡眠平衡、体温、活动量、久坐打断）。
    *   *第三层（时序流）*：日内活动量条形图、连续皮温变化。
*   **展示特点**：**自定义快捷磁贴（Shortcuts）+ 极简非数值化**。首屏顶部磁贴支持拖拽排序。避免直接裸露复杂的生理学绝对数字，用能量槽来降低用户的健康焦虑。

#### 1.4 Garmin Connect
*   **UI 数据分层**：
    *   *第一层（状态）*：**Body Battery（身体电量，0-100）**、**Stress（压力指数，0-100）**。
    *   *第二层（归因）*：今日累计充电量（Charge）与累计消耗量（Drain）。
    *   *第三层（时序流）*：24小时充放电曲线图，背景颜色叠加表示压力状态（橙色为压力，蓝色为休息，灰色为运动）。
*   **展示特点**：**硬核能量起伏图**。像看仪表盘一样看身体能量，曲线波动具有极强说服力。

### 2. 纯软件与数据聚合竞品（Software-Only & Aggregators）

#### 2.1 Gentler Streak (iOS)
*   **UI 数据分层**：
    *   *第一层（状态）*：**Activity Path（活跃波浪通道）**。不强制闭合圆环，而是给出一个绿色的安全负荷波动区间。
    *   *第二层（归因）*：TSB（训练应激平衡）与 TRIMP（训练冲量积分）指标。
    *   *第三层（时序流）*：最近 10 天/30 天的体能趋势曲线。
*   **展示特点**：**反惩罚设计，关怀性语境**。白点在绿色波浪通道内即为 Balance。如果白点超出上限，文案会友好建议“你累了，去休息吧”；并支持向左滑动曲线，预测未来 4 天如果不锻炼，体能状态点会退化到何处。

#### 2.2 Athlytic (iOS)
*   **UI 数据分层**：
    *   *第一层（状态）*：通过重构 Apple Watch 原始数据，生成类似 WHOOP 的 **Recovery** 百分比和建议的今日 **Target Exertion Range（目标负荷区间）**。
    *   *第二层（归因）*：睡眠 HRV（RMSSD 方法计算）、睡眠 RHR 与 60 天平均值的对比。
    *   *第三层（时序流）*：日内活动心率区间百分比。
*   **展示特点**：**平替 WHOOP，纯卡片式排版**。极简卡片式，点击直接滑出二级分析趋势。

#### 2.3 Fitbod (Manual Weight Logger)
*   **UI 数据分层**：
    *   *第一层（状态）*：**3D 人体肌肉热力图（Muscle Recovery Map）**。全身主要肌群以红、黄、绿渐变色标记。
    *   *第二层（归因）*：各肌群的疲劳百分比（0%-100%）。
    *   *第三层（时序流）*：每个动作的 1RM 折线、累计训练吨位（Volume Load）。
*   **展示特点**：**状态可视化直接驱动运动生成**。Fitbod 计算你历史打卡重量与次数，建立各个肌肉的疲劳和消退曲线（6-7天衰减）。点击“开始训练”，系统自动挑选处于绿色（100% 恢复）的肌群组装成一键式训练计划。

#### 2.4 Samsung Health (2026 最新版)
*   **UI 数据分层**：
    *   *第一层（状态）*：**Energy Score（能量分数）** 与 **Daily Activity Rings（步数/时间/卡路里三色弧）**。
    *   *第二层（归因）*：Vitals 卡片（HRV、皮温、血氧）与 Cardio Load（心肺负荷对上限的比例）。
    *   *第三层（时序流）*：单次 GPS 轨迹、连续睡眠分段图。
*   **展示特点**：**AI 聚合的健康五大支柱（Activity, Sleep, Vitals, Nutrition, Mindfulness）**。将心肺活动负荷和长期血管负载结合，从运动追踪升级为全面的全天生命体征复盘。

## 二、 Relty Activity 调研清单与决策机制

基于对上述竞品的剖析，Relty 作为“胸前 1fps 相机 + 胸口 IMU”的设备形态，其 UI 设计机制应如下规划：

### 1. 调研清单 (Checklist)

*   `[ ]` **Balance (客观平衡) 视觉表征**：放弃 Apple Fitness 每天归零重新开始的强迫模式，选择类似 **Gentler Streak 的“Activity Path 活跃通道”**。由于我们没有持续心率，我们将通过端侧 IMU 估算的 Body SMA 与步频，转换为能量消耗值，并在此通道上绘制滚动 7 天的白点曲线。
*   `[ ]` **Goal (目标达成) 图形引导**：由于我们主打 WHO/Canadian 24h 指南，我们的 Activity Goal 应当包含：**中高强度运动时间（MVPA）**、**力量训练（本周肌群覆盖率）**、**久坐打断次数（60分钟中断）**，这三个指标在 UI 上表现为**同心多格进度圆环**，每达成一项，对应的扇区亮起。
*   `[ ]` **日常 Timeline 极简操作**：纯软件的 Hevy 和 Fitbod 要求用户每组都手动打卡，摩擦力过高。Relty 应当在 Timeline 自动渲染出识别好的 Session 卡片（Office / Walking / Running / Gym Workout），只有在力量动作置信度 $< 70\%$ 时，弹出醒目的**“复盘视频”**微交互按钮，用户轻触即可校准动作。
*   `[ ]` **力量板块（Fitness）的肌肉热力图继承**：在 Activity 界面下滑，直接继承 Fitbod 的**肌肉热力图展示**。我们不需要用户手动填重量，直接通过 IMU 动力学特征波形粗略计算负荷（Body SMA 积分值），衰减曲线同样采用 6 天重置，彩色展示“推、拉、腿、核心”今日的酸痛与恢复度。

## 三、 Relty Activity 板块 UI 设计机制

根据以上决策，Relty 页面分为三大模块，其页面关系与数据流向设计如下：

### 1. 双主轨 Dashboard (第一层)
*   **左侧：Activity Balance 盘 (0-100)**：
    *   数据来源：`0.70 * Movement_Guideline_Adequacy + 0.30 * GPAQ_MET_Total`。
    *   视觉：极简圆弧仪盘。若用户没有高强度运动，但在办公中每 60 分钟起身活动了 2 分钟，且累计步行达标，Balance 依然可以获得高分（如 85 分），传达“日常活动结构平衡，没有久坐危害”的健康信号。
*   **右侧：Activity Goal 环**：
    *   数据来源：本周累计 MVPA 分钟数（目标 150 分钟进度条）、本周已覆盖肌群数（目标 6 个）、今日久坐打断次数（目标 5 次）。
    *   视觉：三个嵌套的细线圆环，每天随着用户活动而闭合。

### 2. Daily Timeline 瀑布流 (第三层)
展示今日全天候的 Session 序列，每张卡片对应算法规格书中分类出的 Session：
*   **`办公久坐 (Sedentary)` 卡片**：若连续久坐超过 60 分钟，卡片变橙，显示警告符号 `⚠️ 连续久坐 85 分钟未打断`。
*   **`室外步行 (Walking)` 卡片**：展示步数、平均步频、平均 MET。
*   **`力量训练 (Gym Workout)` 卡片**：
    *   显示本次训练的总时长，以及识别出的动作大类占比（例如：`推 40% / 拉 60% / 腿 0%`）。
    *   **低置信度动作卡片**：如果某一动作置信度 $< 70\%$，卡片展开区出现 `复盘短视频`。用户点击后，弹出 Modal 播放拼接视频，并在下方提供 top-3 的替代动作按钮（如：`平板哑铃卧推`、`平板杠铃卧推`）。用户选择后，状态直接更新。

### 3. 肌肉负荷与恢复状态 (第二层)
*   页面底部的折叠面板，展开后显示极简人体剪影热力图。
*   划分为四大核心肌群：
    *   `推 (Push)`: 胸、肩、肱三头肌。
    *   `拉 (Pull)`: 背、肱二头肌。
    *   `腿 (Legs)`: 臀部、大腿前/后侧、小腿。
    *   `核心 (Core)`: 腹肌、竖脊肌。
*   当系统识别到 Gym Session 里的 L3 动作（如推类动作完成 5 组），该肌肉剪影变红，并在下方显示：`恢复程度：28%，预计还需 42 小时完全恢复`。

## 四、 核心 Story 拆分与执行计划

为了将上述 Activity UI 机制转化为可开发的交互式原型，现拆分为以下 4 个 Story：

### Story 1: 仪表盘核心框架与 Balance/Goal 双轨 Dial
*   **背景与目标**：
    构建 Relty Activity 仪表盘页面的顶部核心组件，直观展示 `Activity Balance` 和 `Activity Goal` 的指标状态。
*   **影响范围**：
    页面首屏、核心 CSS 样式文件、基础模拟数据结构。
*   **具体任务拆分**：
    1. 设计主页面容器，使用 Sleek Dark Mode 风格（深灰背景，微拟物/玻璃态卡片）。
    2. 使用 HTML5 Canvas 或 SVG 绘制 `Activity Balance` 仪盘（圆弧轨道，带动态渐变光晕）。
    3. 绘制 `Activity Goal` 同心进度环（三环嵌套，分别为：MVPA 分钟、力量覆盖、久坐打断）。
    4. 编写基础 JS 数据模型，提供 Balance 和 Goal 的数值接口。
*   **验收标准**：
    - 首屏能够正确载入并渲染两个大仪表盘。
  - 支持传入模拟数据（如 Balance = 85，Goal 三环分别完成 60%, 30%, 100%）并实时渲染出正确弧度。
  - 点击仪盘时，弹出精致的 Tooltip 浮窗，文字解释各自的数据计算来源。
*   **测试要求**：
    - 验证各参数越界时的页面渲染（如完成度大于 100% 时，进度条不溢出截断）。
    - 响应式测试：在 iPhone 模拟器视口（375px - 430px 宽度）下完美居中，无横向滚动条。
*   **相关上下文**：
    - 数据口径：`Activity Balance = 0.70 * Movement_Guideline_Adequacy + 0.30 * GPAQ_MET_Total`。
*   **开发注意事项**：
    - 避免使用任何庞大的第三方图表库（如 Chart.js/Echarts），全部使用原生 CSS 与 SVG/Canvas 渲染，保证极速载入和端侧微控制器仿真的轻量性。

---

### Story 2: Daily Timeline 与多模态 Session 卡片列表
*   **背景与目标**：
    在仪表盘下方构建全天活动的时序 Timeline 列表，用于汇总展示 IMU+1fps 相机判定出的各类日常活动事件（Sessions）。
*   **影响范围**：
    主页面下部区域、数据适配器、时序流 CSS 样式。
*   **具体任务拆分**：
    1. 构建垂直时间轴线，时间节点根据事件的起止时间动态排布。
    2. 实现三类核心事件卡片样式：
       - `久坐卡片`：展示累计久坐时间。若连续久坐 $> 60$ 分钟，卡片背景微变红，显示警告图标与时长。
       - `日常活动卡片 (Walking/Running)`：展示步数、估算 MET、步频等日常有氧参数。
       - `力量卡片 (Gym Workout)`：展示本次训练的总时长，以及识别出的动作大类占比进度条。
    3. 编写模拟 timeline 数据序列（包含 24 小时内的 6-8 个典型 Session 事件）。
*   **验收标准**：
    - 时间轴卡片按时间先后顺序正确从上到下排列。
    - 久坐超时报警卡片视觉样式具有强提示性（黄色/橙色高亮）。
    - 力量卡片能正确渲染出 L3 动作分类比例（如 Push 40%, Pull 60% 的水平占比条）。
*   **测试要求**：
    - 验证多个 Session 卡片重叠或时间冲突时的排布稳定性。
    - 验证长文本场景下（如运动名称极长）卡片是否会撑破页面。
*   **开发注意事项**：
    - 每一个 Session 卡片必须带有一个唯一的 `Session_ID`，以便后续的 Story 3 进行交互对接。

---

### Story 3: 力量训练低置信度（Ambiguous）异步复盘与纠偏 Modal
*   **背景与目标**：
    当系统检测到 Gym Workout 事件中的动作置信度较低（`is_ambiguous: true`）时，为用户提供一段由 1fps 抓拍拼接的短视频，以极低认知负荷完成动作纠偏与手动核对。
*   **影响范围**：
    Gym Workout 卡片内部状态、全局 Modal 弹出框、状态更新逻辑。
*   **具体任务拆分**：
    1. 在力量卡片（Story 2）中，若数据标明 `is_ambiguous: true`，在卡片右下角渲染一个“📷 待确认复盘视频”缩略图按钮，带微弱的呼吸动效。
    2. 设计并实现全局 Review Modal 弹窗。
    3. 在 Modal 内使用 JS 定时器，以 1fps 速度轮播传入的 3-5 张模拟健身抓拍图（模拟稀疏关键帧播放效果）。
    4. 在 Modal 底部生成 Top-3 候选动作按钮。
    5. 实现点击更新逻辑：当用户点击其中一个候选动作时，关闭 Modal，更新对应的 Gym Session 卡片的动作名称，且将 `is_ambiguous` 状态置为 false（消除卡片上的警告标记）。
*   **验收标准**：
    - 点击卡片上的缩略图，Modal 顺滑滑出。
    - Modal 内图片每秒自动切换，并循环播放。
    - 用户点击底部候选按钮（如将“上斜卧推”改为“平板卧推”）后，卡片上的文本立刻更改，置信度红点消失，数据模型中的值发生同步更改。
*   **测试要求**：
    - 验证 Modal 在多次打开、关闭后，定时器（1fps 轮播）被正确销毁和重建，无内存泄漏或轮询加速。
    - 验证在 Modal 打开状态下，背景页面被锁定不可滚动。
*   **开发注意事项**：
    - 模拟的健身图片可以使用 generate_image 提前生成好 3 张，存放在本地，或者使用占位图形表示。轮播时注意加过渡动画以防闪眼。

---

### Story 4: 肌肉恢复热力图 (Muscle Recovery Heatmap) 与指标深度卡片
*   **背景与目标**：
    在 Activity 页面底部，展示由 Gym Workout L3 大类直接驱动的全身主要肌群冷热恢复图，并提供全天活动指标的深度分项卡片（如 GPAQ 三域 METs 分布图）。
*   **影响范围**：
    页面底部面板、肌肉 SVG 矢量图组件、GPAQ 饼图/占比条。
*   **具体任务拆分**：
    1. 绘制或引入一个极简的前/后人体肌群 SVG（划分出：推、拉、腿、核心四大区域）。
    2. 根据传入的肌肉恢复百分比（Push: 30%, Pull: 80% 等），动态改变对应 SVG 路径的填充颜色（红：高疲劳，绿：完全恢复）。
    3. 设计 GPAQ 三域（工作、交通、休闲）METs 分布展示条（采用水平百分比堆叠条呈现，例如 `工作(40%) | 交通(20%) | 休闲(40%)`）。
*   **验收标准**：
    - 页面底部的肌肉图能根据当前的 Gym 训练事件动态改变颜色（例如，若今日有 Push 训练，推肌群区域填充颜色变成红色，其余为绿色）。
    - 肌肉下方显示出对应的建议恢复时间（如 `42小时后完全恢复`）。
    - GPAQ 占比条能够正确计算并渲染出比例。
*   **测试要求**：
    - 验证各肌群百分比数值改变时，SVG 填充颜色的渐变过渡是否正确。
    - 验证无力量训练数据时，肌肉图默认处于 100% 绿色恢复状态。
*   **开发注意事项**：
    - 肌肉热力图可做成折叠面板（Accordion），默认收起，点击后展开，以保证页面层级的清爽，防范信息过载。
