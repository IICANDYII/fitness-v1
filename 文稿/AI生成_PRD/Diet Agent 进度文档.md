## 2. 待确定事项

- Diet Agent 主界面需要呈现哪些核心信息？
- 这些信息之间的优先级如何排序？
- “一餐吃完一日全部热量”和“分成多餐摄入”是否存在科学差异，是否需要纳入 Balance 或解释层？

## 3. Diet Agent 主界面信息建议

首屏需要展示核心指标，同时配合部分分析图表和统计数据，帮助用户快速理解当天的整体饮食情况。

需同步思考不同数据的呈现形式，如数值卡片、进度条、趋势图、对比条、结构占比图等。

### 必须展示

- 今日 Diet Balance 总体状态
- 今日 Goal / Finish 完成情况
- 历史趋势入口

### 可选展示

- 今日最重要的一条饮食反馈
- Balance 分项拆解：饮食结构、热量、宏量营养、关键营养、进食节律
- 每餐记录：早餐、午餐、晚餐、加餐
- 每餐识别出的主要食物
- 每餐热量估算
- 全天总热量估算
- 蛋白质、脂肪、碳水比例
- 蔬菜、水果、全谷物、乳制品、蛋白质等食物组表现
- 高糖、高钠、高饱和脂肪等风险提示
- 饮食记录不完整时的提示
- 识别不确定性 / 置信度提示

首屏建议尽量只放最核心的结论，其他信息可以放在下滑后的模块中。

## 4. Goal / Finish 备注

相比先讨论展示哪一类 Goal，更需要先明确 Goal 应该如何被创建。

当前建议优先思考以下问题：

- 用户是否可以自己直接精确定义 Goal？
- Goal 是否应由系统基于用户当前饮食情况做引导式推荐？
- Goal 是否应以若干预设标签 / 模板的方式供用户选择？
- 用户修改 Goal 的自由度应该有多大？
- Goal 是一次设定长期有效，还是需要按阶段动态调整？

初步倾向是不建议完全让用户自由输入一个精确 Goal，而更适合由系统提供引导或模板化选择，用户再进行确认或微调。

## 5. Balance 计算公式

当前 Diet Balance 暂定公式：

```text
Diet Balance =
0.40 * HEI_2020_available
+ 0.15 * AMDR_Fit
+ 0.20 * RDA_AI_Adequacy
+ 0.10 * Meal_Timing
+ 0.15 * Kcal_Balance
```

其中：

- `HEI_2020_available`：反映整体饮食结构是否接近膳食指南
- `AMDR_Fit`：反映碳水、脂肪、蛋白质比例是否合理
- `RDA_AI_Adequacy`：反映蛋白质、膳食纤维等关键营养是否达标
- `Meal_Timing`：反映进食节律是否合理，目前仍需继续定义
- `Kcal_Balance`：反映全天实际热量是否接近个人目标热量 / 能量需求
