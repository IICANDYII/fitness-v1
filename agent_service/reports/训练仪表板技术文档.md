## 1. 系统概述

训练分析仪表板是一个单页 Web 应用（SPA），用于展示用户的健身训练数据。前端采用纯 HTML + CSS + 原生 JavaScript 实现（无框架依赖），后端为 FastAPI 提供 RESTful API，数据存储在 PostgreSQL 数据库中。

### 1.1 技术栈

| 层级 | 技术 | 说明 |
|------|------|------|
| 前端 | HTML5 / CSS3 / Vanilla JS | 单 HTML 文件，无构建工具 |
| 后端 | Python FastAPI + Uvicorn | `agent_service/reports/api.py` |
| 数据库 | PostgreSQL 15 (pgvector) | Docker 容器 `postgres-pgvector`，端口 5432 |
| 运行 | Docker + Uvicorn | 端口 8000，`launch.json` 配置 |

### 1.2 文件结构

```
agent_service/reports/
├── api.py                      # FastAPI 后端（路由 + 业务逻辑）
├── training_dashboard.html     # 仪表板前端（单文件 SPA）
├── report_viewer.html          # 报告查看器页面
├── plan_viewer.html            # 计划查看器页面
└── svg/                        # 人体肌肉图 SVG 资源
    ├── front-male.svg

    ├── front-female.svg
    └── back-female.svg
```

### 3.2 Fitness Balance 圆环

**位置**：卡片左上角，104×104px 圆形。

**CSS 实现**：
- 外环：`conic-gradient(#10b981 calc(var(--balance)*1%), #e9ecf5 0)` — 绿色进度弧

- 光标球：`::after` 伪元素，12px 白色圆球带绿色光晕阴影，通过 `transform: rotate(calc(var(--balance)*3.6deg))` 跟随进度旋转

**数据绑定**：
```javascript
var balScore = Number(fb.score || 0);
document.getElementById('s-balance').textContent = balScore;
document.getElementById('balance-ring').style.setProperty('--balance', balScore);
```

### 3.3 Fitness Balance 计算公式

> **FitnessBalance = 0.25 × G + 0.50 × S + 0.25 × E**

基于**滚动 7 天窗口**计算（`ref_date - 6` 至 `ref_date`）。

#### G — Guideline Reference Score（指南参考分）

衡量训练是否符合权威运动指南推荐的最低频率和覆盖度：

```
freq_ratio = min(strength_days / 2, 1)
cov_ratio  = covered_groups / 7
G = 100 × min(freq_ratio, cov_ratio)
```

- `strength_days`：7 天窗口内有力量训练的天数
- `covered_groups`：训练覆盖的肌群数量（共 7 大肌群）
- 分母 2 表示每周至少训练 2 天

#### S — Structure Score（结构均衡分）

衡量实际肌群训练分配与目标分配的偏离程度：

```
actual_share[g] = muscle_exposure[g] / Σ muscle_exposure
deviation = Σ |actual_share[g] - target_share[g]|    (对所有 7 个肌群)
S = 100 × max(1 - 0.5 × deviation, 0)
```

目标分配（`_DEFAULT_TARGET`）：

| 肌群 | 腿 | 臀 | 背 | 腹 | 胸 | 肩 | 臂 |
|------|-----|-----|-----|-----|-----|-----|-----|
| 目标占比 | 16% | 14% | 16% | 14% | 14% | 14% | 12% |

肌群曝光量计算规则：
- `exercise_unit = min(sets, 4)` — 单动作有效组数上限 4
- 主练肌群权重：`1.0 × confidence(0.85)`
- 辅助肌群权重：`0.5 × confidence(0.85)`

#### E — Evidence Score（训练证据分）

衡量每次训练的证据质量（置信度、数据完整性等）：

```
evidence_i = 0.35 × confidence + 0.25 × 0.7 + 0.25 × unit_suf + 0.15 × 0
E = 100 × Σ(evidence_i × unit_i) / Σ(unit_i)
```

- `confidence`：固定 0.85（AI 识别置信度）
- `unit_suf = min(exercise_unit / 2, 1)` — 组数充分度

#### 无训练日处理

当选中日期无训练记录时，API 仍返回 `fitness_balance` 数据（基于滚动 7 天窗口），确保 Balance 在休息日也有评分。如果窗口内完全无训练则返回 `score: 0, status: "insufficient_data"`。

### 3.4 训练路径

将动作列表按类别去重后形成路径链，展示训练区域流转。

分类逻辑（前端 `zoneOf()` 函数）：
- **有氧运动区**：跑步、慢跑、快走、动感单车、椭圆机等
- **拉伸放松区**：拉伸、热身、瑜伽、泡沫轴等
- **核心训练区**：卷腹、平板支撑、悬垂举腿等
- **力量训练区**：默认分类

每个区域带有图标：`⌁` 有氧 / `▬` 力量 / `✦` 拉伸 / `●` 核心

## 4. Card 2：肌群分析

### 4.1 SVG 人体热力图

使用嵌入式 SVG 展示前视图和后视图的肌肉激活状态，支持**男/女**两套 SVG 图。

**性别切换**：通过 `#viz-body-wrap` 的 CSS class `show-female` 控制显示哪套 SVG。

**热力渐变**：8 级灰紫渐变色阶 `GRAD8`，未激活肌肉为浅灰色 `#c8cad6`。

```javascript
var GRAD8 = ['#d4d6e8','#bfc2db','#aaadce','#9599c1','#8085b4','#6b70a7','#565c9a','#41478d'];
```

激活度映射：`pct(0-100)` → `GRAD8[Math.floor(pct / 100 * 8)]`

**肌肉 ID 映射**：SVG 中每个肌肉区域有唯一 ID（如 `chest`、`b-lats`），前缀 `b-` 表示背面视图对应区域。`applyHeatmap()` 通过 `querySelectorAll('[id="..."]')` 同时选中正背两面的同名元素。

### 4.2 7 大肌群定义

| 肌群(CN) | 英文 | 包含 SVG ID |
|----------|------|-------------|
| 胸 | Chest | `chest` |
| 肩 | Shoulders | `shoulders`, `front-shoulders`, `rear-shoulders` |
| 臂 | Arms | `triceps`, `biceps` |
| 背 | Back | `lats`, `traps`, `lowerback`, `scapula` |
| 腿 | Legs | `quads`, `hamstrings`, `calves` |
| 臀 | Hips | `glutes`, `hips` |
| 腹 | Abdomen | `abdominals`, `obliques` |

### 4.3 动态肌群摘要

底部显示**主练肌群 / 辅助肌群 / 遗漏肌群**，由后端 `compute_muscle_summary()` 根据当天训练数据动态生成：

```python
# 主练：得分 ≥ 最高组 50% 的肌群
primary = [g for g, s in trained if s >= top * 0.5]
# 辅助：得分 < 最高组 50%
secondary = [g for g, s in trained if s < top * 0.5]
# 遗漏：得分为 0
missing = [g for g, s in group_scores.items() if s == 0]
```

```python
# 主练肌群权重 sets×2，辅助肌群权重 sets×1
# 各肌群占比 = 该肌群总分 / 全部肌群总分 × 100
```

| 参数 | 类型 | 说明 |
|------|------|------|
| `user_id` | string | 用户 ID |

**响应**：`{"gender": "male" | "female"}`

### 7.3 GET /api/daily

当日分析数据。

| 参数 | 类型 | 说明 |
|------|------|------|
| `date` | string | 日期 `YYYY-MM-DD`，默认最近一次训练日 |
| `user_id` | string | 用户 ID |

**有训练日响应字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `date` | string | 训练日期 |
| `duration_min` | int | 训练时长（分钟） |
| `calories` | int | 消耗热量（kcal，MET 计算） |
| `completion_rate` | int | 完成率百分比 |
| `muscle_distribution` | object | 肌群训练占比 `{肌群名: 百分比}` |

```python
{
    "primary": ["chest", "triceps"],      # 主练肌肉 SVG ID

```

动作名称存在别名映射（`EXERCISE_ALIAS` 字典），用于将 AI 识别的短名/变体名转换为 `exercises` 表中的标准 `name_cn`。

## 9. 前端数据流

```
页面加载
  │
  ├── loadUsers()               → GET /api/users        → 渲染用户下拉选择器
  │
  └── init()  [并行请求]
        ├── GET /api/daily      → renderDailyData()      → Card 1 + Card 2
        ├── GET /api/weekly     → renderWeeklyPanels()   → Card 3
        ├── GET /api/calendar   → renderCalendar()       → Card 4
        └── GET /api/user       → applyGender()          → 切换 SVG 性别

用户切换
  └── #user-select change       → 更新 currentUserId → init()

日期点击
  └── .cal-day click            → onCalDayClick(date)
        ├── 更新日历选中态
        └── loadDailyForDate(date) → GET /api/daily?date=... → renderDailyData()
```

### 9.1 关键渲染函数

| 函数 | 作用 |
|------|------|
| `renderDailyData(daily)` | 渲染 Card 1（Balance/统计/路径）+ Card 2（热力图/肌群摘要） |
| `renderTrainingRoute(exercises)` | 渲染训练路径（区域流转链） |
| `renderWeeklyPanels(weekly)` | 渲染 Card 3（每日时长柱状图 + 肌群覆盖环） |
| `renderCalendar(year, month, days, selected)` | 渲染月历格子 |
| `applyHeatmap(muscleData)` | 将肌肉激活数据应用到 SVG 热力图 |
| `renderMuscleBars(dist)` | 渲染肌群分布条形图 |
| `applyGender(gender)` | 切换男/女人体 SVG 显示 |
